## Parte 2: Los 4 errores más comunes (0:15 a 1:01)

**En pantalla**: Diapositiva con las cuatro tarjetas: versión incorrecta y versión correcta.

**Narración**:
Todos los programadores cometen errores, y está bien. Estos son los cuatro errores más comunes.

Primero, olvidar el punto y coma al final de la instrucción. Segundo, las mayúsculas importan: system con minúscula no existe, tiene que ser System. Tercero, abrir unas comillas y no cerrarlas. Y por último, comparar textos con dos signos igual: para comparar texto se usa equals.

En cada tarjeta ves la versión incorrecta y la correcta.

## Parte 3: Buenas prácticas (1:01 a 1:47)

**En pantalla**: JDoodle con el código de ejemplo y las cinco notas de buenas prácticas.

**Narración**:
Escribir buen código también es un hábito. Usa nombres claros: vidasJugador explica qué guarda, mucho mejor que una letra suelta.

Para variables y métodos usa camelCase: la primera palabra en minúscula y las siguientes con mayúscula inicial. Para las clases usa PascalCase: cada palabra empieza con mayúscula, como ReproductorMusica.

Y deja comentarios con dos barras para explicar tu código, sin olvidar la sangría: deja espacios al inicio para ver qué está dentro de qué.

## Parte 4: Cómo leer un mensaje de error (1:47 a 2:18)

**En pantalla**: JDoodle en vivo: se ejecuta el código sin punto y coma y aparece el mensaje de error.

**Narración**:
Cuando algo sale mal, el compilador te muestra un mensaje de error. No es un fracaso: es una pista.

Mira este ejemplo. Nos dice el archivo y la línea donde está el problema. ¿Qué pasó? Aquí, que esperaba un punto y coma. Y con una flechita marca el lugar.

Lee siempre el primer error y arréglalo primero.
